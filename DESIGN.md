# Holographic agent interface

An office worker directs a projected team through voice and short hand gestures. Use one restrained, cinematic holographic space inspired by Tony Stark's JARVIS: deep blue-black surfaces, cyan light, precise fine rings, subtle projection depth and readable labels. No cute animals, office scenery, dashboard tabs, typed composer or button bars.

Keep the original glowing, floating, microphone-responsive voice orb. It starts and pauses both microphone and camera. Agent cores animate from actual task state: quiet breathing while waiting, rotating segmented rings while working, a short completion pulse and checkmark when finished, and an amber warning when a task needs attention. Positions stay fixed for gesture targeting. Reduced motion keeps static state glyphs.

Represent outputs as small holographic document, grid, image or slide objects. Multiple deliverables form one file stack next to their creator. Point and pinch opens a readable detail surface. Known filenames can be opened by voice without starting another task. Technical activity is secondary, and details never dismiss because the pointer leaves.

Use system sans typography, generous gesture targets, restrained lighting, and no fake metrics, decorative terminal output or dense controls.

Start with a wider field of view and generous spacing so users can explore by hand and make room for more assets. Keep asset previews inside the canvas: native page rendering for PDF, embedded image/media and static HTML views, tables for spreadsheet data, and readable document/slide content. Never send selection to another browser tab or default app.

## Result presentation lifecycle

New completed tasks with generated files enter a queue. The presenting agent moves from its stable home slot to a dock beside a floating screen, which unfolds from the agent with a luminous tether. The screen uses real inline asset readers. File switching keeps the presenter docked. Closing by pinch, Escape or voice folds the screen back first, then returns the agent to its central home slot. The next queued result can present after the return finishes. Existing history does not auto-open on page load, and a new completion never takes over a detail surface already being read. Reduced motion uses the same lifecycle with immediate state changes.
